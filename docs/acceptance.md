# Astra 底座设计验收表

本文用于当前最小底座的设计和实现验收。它描述可观察行为；标记为 `[x]` 的项目已有代码与回归测试或明确的实现证据，未勾选项目是有意保留到后续阶段的边界。

## 边界验收

- [x] Kernel 不依赖任何外部项目或平台的具体类型。
- [x] Persona、Memory、Agent、设备和平台逻辑都有明确的领域归属。
- [x] Workflow 可以作为 Component，但不要求 Kernel 理解业务流程。
- [x] Workflow 的最小串行、路由和子流程调用语义可以被验证。
- [x] Event 是事实通知，不隐式承担命令或请求响应职责。

## 能力验收

- [x] Capability 有身份、版本、输入、输出和交互模式。
- [x] Provider 缺失、版本不兼容和歧义解析会确定性失败。
- [x] 一次 Invocation 会固定自己的 Provider Binding。
- [x] 调用方替换 Provider 时无需依赖 Provider 内部实现。
- [x] JSON 可以表达当前启用组合、Capability 绑定和运行参数，但不取代 Workflow 运行语义。
- [x] 配置中的 Capability 绑定会在应用前匹配已启用组件的能力和版本。
- [x] JSON composition 可以执行已注册 Workflow 的串行、连续并行组和无条件单出边跳转。

## 执行验收

- [x] Run、Invocation、Scope 和领域身份可以区分。
- [x] 父 Run 取消会向子调用传播。
- [x] 后台任务必须显式脱离父 Scope。
- [x] 已结束执行不会接收迟到结果。
- [x] Kernel 终态与领域完成事实不会混淆。
- [x] 一次 Run 固定自己的组合代际，运行中不发生组件或 Provider 替换。
- [x] 配置级 Generation 重载先校验和编译，失败不发布，旧 Run 排空后释放旧代际。
- [x] Runtime 停止由外部控制平面发起，活跃 Run 内部调用停止会被确定性拒绝。

## 流和事件验收

- [x] Stream 保持顺序并且只有一个终态。
- [x] Stream 取消可以到达生产者并释放资源。
- [x] Event 订阅绑定 Scope，Scope 停止时自动注销。
- [x] 订阅者异常不会破坏其他订阅者或发布方。
- [x] 第一阶段不会把 Token 或音频分块默认广播到 EventBus。

## 插件和日志验收

- [x] 可信本地插件可以离线发现、校验、载入和停止。
- [x] 插件载入失败不会留下半注册状态。
- [x] 插件配置通过统一入口按实例命名空间管理，并由插件 Schema 提供默认值、迁移和校验。
- [x] 插件配置在启动前固定，运行中的配置切换不会替换插件组件或触发组件生命周期变化。
- [x] 日志记录通过统一结构化数据接口产生，并关联 Run、Invocation、Scope 和 Component。
- [x] 没有日志输出插件时仍然可以获得最小诊断信息。
- [x] 日志输出失败不会阻塞主流程，结构化敏感字段会脱敏；日志消息模板不承载密钥值。

## 权限和副作用验收

- [x] 权限拒绝发生在 Provider 执行之前。
- [x] Runtime 停止不会假定外部业务副作用自动撤销。
- [x] Managed Resource 的释放有明确 Owner。
- [x] External Effect 声明 `retry_safe=true` 时必须提供幂等键，未声明安全策略的能力不会被 Runtime 自动重试。

## 资源与性能验收

- [x] 并行子 Workflow 具有可配置并发上限，取消资源额度等待不会泄漏。
- [x] EventBus 异步订阅和事件触发 Workflow 分别具有待处理上限，超限有丢弃诊断。
- [x] NonBlockingLogSink 具有有界队列，队列满时不阻塞主执行。
- [x] Stream 采用消费者驱动的单步读取，不建立内部无界缓存，取消会关闭生产者。
- [x] 本地性能基线支持显式阈值门禁，插件发现与依赖扫描不进入消息热路径。

## 当前验收说明

当前 44 个回归测试覆盖上述已勾选行为，并包含第一条原生消息响应插件的端到端链路。更复杂的 Stream 缓存和统一资源配置属于后续扩展，不是首轮底座完成条件。
