# ADR-0001：先建立项目设计基线，再实现 Runtime

## 状态

已决定。

## 背景

Astra 的目标是提供可组合的 Component Runtime。项目同时涉及组件、能力、工作流、作用域、生命周期、流、事件、权限和外部副作用。若直接从代码开始，容易把某个具体应用的业务结构误写进内核，并在没有验证用例的情况下冻结过大的公共 API。

## 决策

仓库第一阶段采用文档优先方式：

1. 归档 Vision 1.1 原始输入。
2. 先定义项目愿景、硬边界和核心术语。
3. 将长期原则、候选设计、待验证问题和暂缓方向分开记录。
4. 在实现代码之前，形成最小 Kernel Contract RFC 和对应的验收场景。
5. 第一轮实现范围限定为单进程、本地 Python Runtime。

## 结果

这样可以先确认哪些责任属于 Kernel，哪些责任必须留在领域组件；也可以在公共接口冻结前发现 Scope、取消、权限、事件和副作用语义中的冲突。

代价是仓库初期不会提供可运行代码。这个阶段的完成标准是边界和验证目标清楚，而不是产生一个看起来完整的框架骨架。

## 后续触发条件

该触发条件已经满足：Kernel Contract、边界和关键验收场景已形成，仓库已经进入并完成最小 Runtime 的首轮实现。本文保留为历史决策，后续公共契约仍需通过用例和回归验证后再扩展。
