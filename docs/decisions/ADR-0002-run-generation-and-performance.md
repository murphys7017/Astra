# ADR-0002：运行代际固定与性能不回退

## 状态

已决定。

## 背景

Astra 需要支持插件离线载入、Workflow 作为 Component，以及消息流程的动态组合。同时，AG99 和 AG99live 已经拥有经过实际使用验证的请求、流式输出和实时表现链路。运行时如果在一条消息执行过程中替换组件，或者让所有高频数据都经过通用调度层，会破坏可追踪性并造成性能回退。

## 决策

1. 每个 Workflow Run 固定自己的 Workflow Definition、Profile Generation 和能力绑定策略。
2. 每个 Invocation 固定自己的 Provider Binding。
3. 插件更新、配置变化和 Provider 替换只影响新的 Run。
4. 旧 Generation 进入排空状态，等待现有 Run 结束后再停止和释放。
5. 插件发现、依赖解析、组件启动和 Profile 重组不进入消息热路径。
6. 同进程调用优先使用已解析的本地绑定，避免重复扫描、重复序列化和隐式事件转发。
7. Token、音频分块和逐帧表现不默认经过 EventBus 或 Kernel 调度。
8. AG99 迁移先使用薄适配，保留已有领域 Runtime 的内部并发、缓存和实时链路。

## 结果

一次消息的行为可以复现、追踪和安全收束；配置更新不会破坏运行中的执行；底座的额外开销可以单独测量；AG99 和 AG99live 可以逐步迁移，而不需要一次性重写。

## 验证

使用迁移前后的相同 Provider、输入和配置，比较启动时间、首响应、首 Token、完整响应、流式间隔、取消延迟、CPU、内存和实时播放稳定性。热路径额外开销先按低个位数百分比设定预算，再由实测结果校准。
