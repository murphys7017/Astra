# Astra 项目愿景

## 项目定义

Astra 是一个让开发者自由组织智能系统的可组合组件运行时。它提供统一的组件装载、能力解析、能力调用、流式交互、路由、事件、作用域和生命周期机制，但不规定所有应用必须采用同一种聊天流程、Agent 流程或 Persona 结构。

系统行为由组件组合和 Workflow 定义。模型、记忆、工具、Agent、路由器、输入输出设备和身体运行时，都可以通过组件提供能力。

## 核心关系

```text
Component 提供 Capability
Workflow 组合 Capability
Runtime 管理执行、生命周期和资源
Application 选择组件与工作流
```

核心判断是：能力由组件提供，行为由组合定义，执行由运行时保障，领域复杂度留在领域组件内部。

## 长期原则

1. Component 是独立装载、替换和生命周期管理的单位。
2. Capability 是调用方依赖的稳定契约，调用方不依赖提供者的内部实现。
3. Workflow 可以消费能力，也可以作为 Component 对外提供能力。
4. Runtime 只负责通用运行机制，不理解 Persona、Memory、设备表现或具体 Agent 策略。
5. 本地和远程可以使用相同的能力语义，但远程部署不是第一阶段目标。
6. 资源所有权、取消传播、权限边界、外部副作用和执行诊断必须可以追踪。
7. 公共抽象以实际用例和验证结果为依据，不为假设中的扩展提前增加复杂层次。

## 成功标准

Astra 的成功不由内核包含多少功能决定，而由以下行为决定：

- 新组件可以低成本接入并声明能力。
- 同一能力可以替换实现，调用方无需修改。
- 开发者可以定义多条 Workflow，并让它们通过明确的调用、流和事件协作。
- 执行具有可追踪的因果关系、作用域和终态。
- 取消、资源清理、权限拒绝和迟到结果能够安全收束。
- 内核保持领域中立，不逐渐变成某个具体产品的业务框架。

## 当前阶段

项目已经完成最小本地 Runtime 的首轮实现和验证。当前实现包含 Component、Capability、Workflow、Scope、Run、Invocation、Stream、EventBus、可信离线插件、JSON 启动配置、插件实例配置 Schema、权限和结构化日志；Python Workflow 仍是内部语义的主要承载方式，JSON 只编排已经注册的 Workflow。

当前仍不冻结完整 Python API、远程协议、Workflow DSL、插件生态或自动适配层。插件配置由统一入口按实例命名空间管理，Schema 负责默认值、迁移和校验，启动后保持固定。配置级 Generation 切换、外部副作用契约和并行/EventBus/日志资源边界已经完成首轮实现；Stream 采用消费者驱动的单步读取，插件组件热替换和更复杂的统一资源策略属于后续能力。
